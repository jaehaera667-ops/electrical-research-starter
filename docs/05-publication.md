# 05｜期刊、会议、GitHub 成果怎么评价

先记住一句话：**“被什么数据库收录”与“这个成果质量有多高”不是一回事。**

## 1. 期刊和会议不是同一套评价体系

### 期刊

常见信息包括：

- SCIE / ESCI：Web of Science 核心合集中的期刊索引
- Scopus：Elsevier 的文献数据库
- EI Compendex：工程领域重要数据库
- JCR Q1–Q4：期刊在对应学科中的相对分区

粗略理解：

- Q1：前 25%
- Q2：25%–50%
- Q3：50%–75%
- Q4：后 25%

但同一本期刊可能属于多个 category，因此分区也可能不同。

### 会议

会议通常没有一个像 JCR Q1–Q4 那样全球统一的分区体系。

会议要看：

- 主办/技术赞助组织
- 历史和领域声誉
- full paper 还是 abstract
- peer review 是否严格
- 论文集进入哪里
- 本领域教授是否认可

## 2. IEEE 到底代表什么

IEEE 是专业学会和重要出版/会议组织，不是一个“质量分数”。

所以：

- IEEE conference ≠ 自动高水平会议
- IEEE journal ≠ 自动 Q1
- “IEEE + EI”只能说明出版/检索属性的一部分，不能单独证明学术水平

## 3. EI 是什么

大家常说“EI会议”，通常指会议论文集被 EI Compendex 检索。

它回答的是：

> 这篇会议论文是否进入某个工程文献数据库？

而不是：

> 这篇论文是否一定很强？

普通 EI 会议和领域旗舰会议之间可能差距很大。

## 4. 为什么“SCI Q2”有分量

对电气工程尤其是电力系统、新能源等方向，一篇正规 SCIE/JCR Q2 期刊论文通常已经属于有明显研究训练价值的成果。

但 Q2 内部仍然差异很大。真正判断时还要看：

- 具体期刊
- 领域声誉
- 文章类型
- 你的作者顺序和真实贡献
- 研究是否能讲清楚

**一篇你真正主导、能完整解释的 Q3/Q2，通常比一篇自己说不清楚的挂名论文更有价值。**

## 5. GitHub 成果怎么评价

GitHub 没有统一的“80分/90分”。它的价值在于公开、可验证的过程记录。

从弱到强：

1. Star/Fork：关注或收藏
2. 自己跑通项目：学习经历
3. 独立 case study：项目成果
4. issue：参与讨论
5. PR：提交实际改动
6. PR 被 review + merge：通过外部维护者验证
7. 多次进入 release：稳定贡献
8. maintainer/core contributor：长期核心贡献
9. 研究软件论文/基于项目发表论文：学术成果

GitHub 不替代论文，但能证明“你到底做了什么”。

## 6. 申请博士时看什么

通常不是机械按：

> EI = 5 分，Q3 = 10 分，Q2 = 20 分

教授更关心：

- 你具体做了什么
- 是否是主要贡献者
- 能否解释模型和实验
- 有没有独立解决问题的迹象
- 推荐信怎么评价你
- 与课题组方向是否匹配

## 7. 常见宣传红旗

看到下面这些说法时要额外核实：

- “两个月保证 SCI Q2 录用”
- “交钱保证第一作者”
- “不用做实验，老师包写”
- “Q1 conference”但说不清是哪套排名
- “IEEE会议，所以一定很强”
- “保证 EI 检索”但没有清晰出版/往届记录

## 8. 第一次科研的合理目标

更健康的顺序：

> 先按正规研究标准把项目做完整 → 再根据实际创新和实验质量选择 venue。

第一次可以把 Q2/Q3 作为潜在投稿目标，但不要把“分区”当作科研项目本身。
