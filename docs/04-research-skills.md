# 04｜真正需要掌握的科研技能

科研不是“会不会手敲代码”的比赛。现在更合理的分工是：**你负责研究判断，AI负责大量实现。**

## 1. 把方向变成问题

方向不是问题。

“储能优化”只是方向；真正的问题应该像：

> 在高光伏渗透率下，考虑电池退化后，现有储能调度策略是否仍然具有经济优势？

一个合格问题至少包含：对象、条件、要比较/解释的现象。

## 2. 文献检索

第一次不追求读很多。

目标是找到：

- 1–2 篇综述/教程类文章
- 2–4 篇与你问题最接近的论文
- 1 篇适合复现的基线论文

检索时记录关键词、数据库、年份和为什么保留这篇。

## 3. 读论文

先回答五个问题：

1. 它解决什么问题？
2. 为什么这个问题值得解决？
3. 方法的核心是什么？
4. 用什么实验验证？
5. 作者自己承认哪些局限？

不要第一次就逐字翻译全文。

## 4. 建模

你至少要能说清：

- 输入是什么
- 状态/决策变量是什么
- 目标函数是什么
- 约束/控制逻辑是什么
- 输出指标是什么

AI 可以帮你把数学模型翻成 Python/MATLAB，但数学意义要由你确认。

## 5. 复现

复现不是“复制原作者代码”。

真正训练的是：

> 论文 → 结构化规格 → 实现 → 结果 → 差异解释

允许用 AI 写大部分代码，但你必须知道每个核心模块在做什么，并能发现单位、符号、时间步、约束、数据泄漏等问题。

## 6. 实验设计

至少考虑：

- baseline 是否公平
- 参数是否有物理/工程依据
- 是否只在一个 case 上有效
- 是否有敏感性分析
- 是否存在极端或反例场景
- 输出指标是否真的能支撑结论

## 7. 验证

**代码能跑 ≠ 模型正确。**

优先做：

- 数量级检查
- 单位检查
- 与标准算例/已知结果对照
- 极端参数检查
- 换一个 case 验证
- 与另一工具/方法交叉检查（有条件时）

## 8. 解释结果

看到“方法 A 比方法 B 好”远远不够。

要继续问：

- 为什么？
- 在什么条件下成立？
- 哪些条件下不成立？
- 结果是否符合电气物理常识？
- 有没有其他解释？

科研能力往往就体现在这里。

## 9. 可复现性

至少保存：

- 软件/依赖版本
- 输入数据
- 参数配置
- 随机种子（如有）
- 运行命令/步骤
- 原始结果
- 生成图表的脚本

## 10. Git / GitHub

新手先会这几个就够：

- commit：记录一次有意义的修改
- branch：隔离实验/功能
- README：说明怎么运行
- issue：记录问题/计划
- PR：以后参与公共项目时再重点学

## 11. 科研写作

论文最基本的逻辑：

> 为什么要做 → 现有方法缺什么 → 我做了什么 → 怎么验证 → 结果说明什么 → 有什么局限

写作不是堆“高级词汇”。逻辑清楚比华丽更重要。

## AI 应该做什么

适合交给 AI：

- 写/重构代码
- 查 API 和报错
- 数据清洗
- 画图
- 生成初版实验脚本
- 文献初筛和摘要对比
- 英文润色
- 帮你检查可能遗漏的实验

## AI 不应该替你决定什么

必须由你把关：

- 研究问题是否值得做
- 文献是否真的支持你的判断
- 模型假设是否合理
- baseline 是否公平
- 结果是否可信
- 异常结果为什么出现
- 结论是否超出证据
- 论文中的贡献是否真实属于你

## 第一个项目开始前的最低技能

你不需要“全会”，但至少应做到：

- [ ] 能读懂本科层面的电力系统/控制公式
- [ ] 会运行 MATLAB 或 Python 脚本
- [ ] 会让 AI 按明确需求修改代码
- [ ] 会画基本曲线/表格
- [ ] 知道什么是 baseline
- [ ] 知道“仿真结果要验证，不能只看是否运行成功”
- [ ] 愿意记录失败和异常结果

满足这些，就可以边做边学，不需要先闭门学半年编程。
